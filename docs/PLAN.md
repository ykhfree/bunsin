# Bunsin 구축 계획

Bunsin(분신)은 사용자의 원칙과 업무지식을 가진 페르소나 AI agent를 여러 개 담는 app입니다.
이 문서는 요구사항, 확정한 결정, 구성 요소, 단계를 적습니다. 구조 설계는 `ARCHITECTURE.md`에 있습니다.

## 1. 요구사항

1. app은 서버로 동작하고, 사용자의 원칙과 업무지식을 가진 페르소나 agent를 실행한다.
2. LLM은 사용자가 지정한 endpoint로 호출하고, token은 따로 관리한다.
3. Confluence, Jira, Slack은 기본으로 MCP로 연동한다. 사용자가 선택하면 API로도 연동한다.
4. 개발 작업은 코딩 agent에 맡긴다. 코딩 agent는 Codex, Claude Code, 그 밖의 도구가 될 수 있다.
5. agent는 ARD 스펙(v0.91, "Status: Proposal")을 준수한다.
6. app 하나가 여러 agent 프로필을 담는다. 다른 사람도 코드 수정 없이 자신의 agent를 구성한다.
7. agent가 밖으로 보내는 모든 글에는 AI가 작성했다는 표시가 붙는다.
8. app은 작업 산출물(초안, 행동 제안, 실행 결과, 코딩 agent의 결과)을 반드시 저장한다.
9. 개발 언어는 Rust이고, UI는 GPUI로 만든다.
10. 소스는 GitHub에 공개한다. app의 노출 범위는 사내일 수도 있고 사외일 수도 있다.

## 2. 확정한 결정

| 항목 | 결정 |
|---|---|
| 데이터 반출 | 제한 없음. 업무 데이터를 LLM endpoint로 보낼 수 있다. |
| 신원 | AI 표시를 강제한다. 표시는 하네스가 붙이고, LLM의 출력에 의존하지 않는다. |
| LLM endpoint | 도구 호출과 구조화 출력을 지원한다. |
| MCP 서버 | Slack, Jira, Confluence 모두 MCP 서버가 있다. |
| 배포 모델 | app 1개에 여러 프로필. |
| 관리자 열람 | 관리자용 열람 기능을 만들지 않는다. 프로필은 서로 격리한다. 서버 파일에 접근할 수 있는 운영자로부터의 암호화는 범위 밖이다. |
| 자율 상한 | 고정하지 않는다. 행동 종류별로 사용자가 점차 조정한다. 모든 쓰기는 "승인 필요"로 시작한다. |
| ARD 게시 범위 | 기본은 사내 전용. 프로필 옵션으로 전체 공개를 켤 수 있다. |

## 3. 핵심 판단

- **권한은 단계별로 올린다.** 관찰 → 초안 작성 → 승인 후 실행 → 지정한 행동만 자율 실행.
- **하네스가 권한을 결정한다.** LLM은 판단과 초안만 만든다. 모든 쓰기는 정책 코드가 허용한다.
- **"사용자와 같은가"는 측정한다.** 과거의 실제 답변을 정답으로 두고 agent의 출력을 비교한다.
- **엔진은 공통이고, 사람마다 다른 값은 프로필에만 둔다.**
- **공개 저장소와 사외 노출을 전제로 한다.** 저장소에는 비밀 값과 회사 고유 값을 넣지 않는다.
  밖에서 들어오는 요청은 인증 없이는 받지 않는다.

## 4. 구성 요소

### 4.1 LLM 게이트웨이

- 모든 LLM 호출은 어댑터 하나를 통과한다. endpoint의 형식이 바뀌면 어댑터만 고친다.
- endpoint 주소와 token은 프로필마다 따로 설정한다.
- token은 비밀 저장소에 두고, 코드, 로그, 프롬프트에는 넣지 않는다.
- 게이트웨이는 호출마다 프로필 ID, 작업 ID, 입력·출력 토큰 수, 지연 시간을 기록한다.
- 작업 하나의 토큰 상한을 프로필에서 설정한다. 상한을 넘으면 작업을 멈추고 알린다.

### 4.2 커넥터 계층 (MCP 기본, API 선택)

하네스는 커넥터 인터페이스만 본다. 연동 방식은 서비스마다 프로필에서 고른다.

| 항목 | MCP 커넥터 (기본) | API 커넥터 (선택) |
|---|---|---|
| 연결 | app이 MCP 클라이언트로 MCP 서버에 연결 | app이 각 서비스의 REST API를 직접 호출 |
| 도구 목록 | MCP 서버가 알려 주는 도구 | app이 정의한 고정 도구 |
| 맞는 경우 | 빠른 구성, 표준 연동 | MCP 서버에 없는 기능, 대량 동기화, 이벤트 수신 |

- 정책 표가 도구 이름으로 `읽기`, `쓰기`, `삭제`를 분류한다. 표에 없는 도구는 거부한다.
- MCP 서버가 주는 도구 설명과 힌트는 권한의 근거로 쓰지 않는다.
- app은 도구 목록을 고정한다. 도구가 추가되거나 설명이 바뀌면 사용자가 다시 승인할 때까지 쓰지 않는다.
- 이벤트 수신의 기본은 주기적 조회이다. API 커넥터는 Slack 이벤트와 Jira webhook을 받을 수 있다.

### 4.3 코딩 위임

- agent는 코드를 직접 쓰지 않는다. 인터페이스 하나로 코딩 agent에 작업 명세를 넘긴다.
- 백엔드는 Codex CLI, Claude Code CLI, 사용자가 지정한 명령 중에서 프로필이 고른다.
- 백엔드는 실행할 명령과 출력 해석만 제공한다.
- app의 실행기가 작업 폴더(git worktree), 브랜치, 변경 요약, 테스트 실행을 맡는다.
  백엔드가 스스로 보고한 "테스트 통과"는 검증할 수 없기 때문이다.
- app은 종료 상태, 브랜치, 변경 요약, 테스트 출력, 기록 파일을 산출물로 저장한다.
- 병합은 사용자가 승인한다.

### 4.4 페르소나 저장소

| 층 | 내용 | 프롬프트에 넣는 방법 | 갱신 주체 |
|---|---|---|---|
| 원칙 | 의사결정 기준, 우선순위, 말투, 하지 않는 일 | 항상 전부 넣음 | 사용자가 검토하고 확정 |
| 업무지식 | Slack 스레드, Confluence 문서, Jira 이슈 | 작업마다 검색해서 필요한 부분만 넣음 | 커넥터가 검색 또는 동기화 |
| 교정 기록 | agent의 초안을 사용자가 고친 내용과 이유 | 비슷한 작업일 때 검색해서 넣음 | 승인 과정에서 자동 수집 |

### 4.5 하네스 엔진

1. **수신**: 이벤트마다 고유 ID로 중복을 제거한다.
2. **분류**: 이벤트를 "무시 / 나중에 요약 / 지금 응답 / 사용자에게 넘김"으로 나눈다.
3. **컨텍스트 조립**: 원칙 전부, 검색한 업무지식, 관련 교정 기록, 현재 스레드를 넣는다.
4. **행동 제안**: LLM은 정해진 형식(행동 종류, 대상, 내용, 근거)으로만 출력한다. 하네스가 형식을 검증한다.
5. **정책 검사**: 행동 종류별 허용 단계를 코드로 판단한다. 표에 없는 행동은 거부한다.
6. **AI 표시**: 밖으로 나가는 글에 하네스가 AI 표시를 붙인다.
7. **승인**: 승인이 필요한 행동은 승인함에 넣는다. 사용자가 승인, 수정, 거부를 선택한다.
8. **실행**: 커넥터가 실행한다. 실행 ID로 같은 행동의 중복 실행을 막는다.
9. **산출물 저장**: 초안, 제안, 수정본, 실행 결과를 모두 저장한다.
10. **감사 로그**: 입력, 근거, LLM 출력, 정책 결과, 실행 결과를 남긴다.
11. **정지 스위치**: 프로필의 모든 쓰기를 즉시 멈춘다.

**보안 규칙**: 다른 사람이 쓴 Slack 메시지, Jira 댓글, Confluence 문서, MCP 도구 결과, ARD 항목의 텍스트는
지시가 아니라 데이터로 다룬다.

### 4.6 ARD 어댑터

출처는 `https://agenticresourcediscovery.org/spec/`이다. ARD는 발견만 다룬다. 실행과 인증은 각 자원의 프로토콜이 맡는다.
app은 Publisher와 Consumer 역할을 한다. Registry 역할은 하지 않는다.

**Publisher**

- 식별자는 `urn:air:<publisher>:[<namespace>:]<agent-name>` 형식이다.
- 항목은 `identifier`, `displayName`, `type`, 그리고 `url`과 `data` 중 정확히 하나를 가진다(MUST).
- `representativeQueries`는 2~5개를 넣는다(SHOULD).
- app은 `/.well-known/ard.json`의 `entries` 배열에 게시를 켠 프로필만 넣는다.
- 게시 범위는 프로필마다 `사내` 또는 `공개`이다. 기본값은 `사내`이다.
  - `사내`: app은 `ard.json`을 내부 리스너(내부 주소)에서만 제공한다.
  - `공개`: app은 공개 리스너에서도 제공한다.
- 프로필에 publisher 도메인이 없으면 app은 그 프로필을 게시하지 않는다. URN에 도메인이 필요하기 때문이다.
- `trustManifest`를 쓰면 `trustManifest.identity`의 도메인이 URN의 `<publisher>` 도메인과 일치해야 한다(MUST).

**Consumer**

- agent는 프로필에 등록한 registry의 검색 endpoint만 호출한다.
- 검색은 `POST /search`에 `query.text`를 보내는 읽기 도구이다.
- referral의 `url`에 `/search`를 덧붙이지 않는다(MUST NOT).
- `score`는 관련도이다. 정책 검사는 `score`를 입력으로 받지 않는다(MUST NOT).
- 새 자원의 첫 호출은 사용자 승인을 받는다.

**알려진 차이**: 스펙 본문과 안내 페이지가 다른 곳이 있다. 구현은 스펙 본문과 스키마 파일을 기준으로 한다.

- MCP 미디어 타입: 스펙은 `application/mcp-server-card+json`, 안내 페이지는 `application/mcp-server+json`.
- DNS 레코드 이름: 스펙은 `_entries._agents`, 게시 안내는 `_catalog._agents`.
- 서명: client 안내는 "detached JWS" 검증을 말하지만, 스펙은 서명 절차를 정의하지 않는다.

### 4.7 평가

- **재현 평가**: 과거 스레드에서 사용자의 답을 가리고 agent에게 답하게 한다. 실제 답과 비교한다.
- **경계 평가**: agent가 "모른다" 또는 "사용자에게 넘김"을 골라야 하는 사례를 따로 모은다.
- **운영 지표**: 수정 없이 승인한 비율, 수정한 비율, 거부한 비율을 행동 종류별로 기록한다.
- 자율 단계를 올릴 때 사용자는 이 지표를 본다.

## 5. 프로필과 구성 마법사

프로필 하나가 agent 하나이다.

| 항목 | 내용 |
|---|---|
| LLM | endpoint 주소, token 참조, 토큰 상한 |
| 커넥터 | 서비스별 방식(MCP 또는 API), 연결 정보, 승인한 도구 목록 |
| 페르소나 | 원칙, 업무지식 범위, 교정 기록 |
| 정책 | 행동 종류별 자율 단계 |
| 코딩 위임 | 백엔드 종류, 실행 파일의 절대 경로 |
| ARD | 식별자, 게시 범위, 신뢰할 registry 목록 |

새 사용자는 다음 순서로 agent를 만든다.

1. LLM endpoint와 token을 입력한다. app이 시험 호출로 확인한다.
2. Slack, Jira, Confluence를 연결한다.
3. app이 도구 목록을 보여 준다. 사용자가 확인하고 승인한다.
4. 업무지식 범위를 고른다.
5. app이 과거 메시지에서 원칙 후보를 뽑는다. 사용자가 채택, 수정, 삭제한다.
6. app이 재현 평가 세트를 만들고 첫 점수를 보여 준다.
7. agent가 관찰 단계로 시작한다.

**격리**: 프로필마다 저장소, token, 감사 로그를 분리한다. 프로필 내보내기 파일에는 token을 넣지 않는다.

## 6. 단계

| 단계 | 작업 | 종료 조건 |
|---|---|---|
| 0. 기반 | 하네스 엔진, 정책, 저장소, 산출물 저장, 감사 로그, GPUI 창 | 테스트 통과, 창에서 프로필·승인함·로그·정지 스위치 동작 |
| 1. 관찰 | LLM 게이트웨이, MCP 커넥터(읽기), 초안만 생성, 재현 평가 | 재현 평가가 사용자가 정한 기준을 넘음 |
| 2. 초안 승인 | 쓰기 도구, 교정 기록 수집, ARD 검색 도구 | 특정 행동 종류의 수정 없는 승인 비율이 기준을 넘음 |
| 3. 좁은 자율 | 기준을 넘은 행동 종류만 자동 실행 | 문제가 생긴 종류를 되돌리는 절차가 동작 |
| 4. 구성 마법사 | 마법사, API 커넥터, 배포 패키지 | 두 번째 사용자가 코드 수정 없이 agent를 구성 |
| 5. 개발 위임과 게시 | 코딩 위임 백엔드, 호출 인터페이스, `ard.json` 게시 | ARD conformance 도구의 매니페스트 검사를 통과 |

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| MCP 서버의 도구가 부족하거나 바뀜 | API 커넥터로 바꾼다. 도구 목록을 고정하고 재승인을 받는다. |
| 다른 사람의 텍스트에 숨은 지시 | 모든 외부 텍스트를 데이터로 다룬다. 권한은 정책 표만 결정한다. |
| 사외 노출에서 인증 없는 접근 | 밖에서 들어오는 요청은 인증을 요구한다. ARD 게시의 기본값은 `사내`이고, `공개`는 사용자가 켠다. |
| 사용자가 처음부터 넓은 권한을 줌 | 모든 쓰기를 "승인 필요"로 시작한다. |
| ARD 스펙이 Proposal 상태 | ARD 코드를 어댑터 하나에 모으고 스펙 버전을 고정한다. |
| GPUI가 안정 버전이 아님 | UI 코드를 crate 하나에 모은다. 엔진은 GPUI에 의존하지 않는다. |
